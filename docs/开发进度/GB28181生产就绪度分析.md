## 🔍 核心问题详细分析

### 1. ⚠️ SSRC 管理问题（你提到的关键点）

#### 问题描述
在 `CommandDispatcher.php` 第 515 行：

```php
// ❌ 当前实现：固定值
$sdp .= "y=0100000001\r\n";  // 硬编码 SSRC
```

在 `GB28181Handler.php` 第 1628 行语音对讲中：

```php
// ✅ 临时方案：随机生成
$ssrc = $this->generateSsrc();  // 生成随机10位数字

private function generateSsrc(): string
{
    return str_pad((string)rand(1000000000, 9999999999), 10, '0', STR_PAD_LEFT);
}
```

#### AKStream 的做法

AKStream 在 VideoChannel 表中为每个通道分配唯一的 SSRC：

```csharp
// AKStream: VideoChannel 表字段
public class VideoChannel
{
    public string MainId { get; set; }  // SSRC 的 CRC32 十六进制
    public string Ssrc { get; set; }    // 10位数字，自增生成
    public string StreamId { get; set; } // 等于 MainId
}

// SSRC 生成：
// 1. 从数据库读取最大 SSRC
// 2. 自增 +1
// 3. 确保全局唯一
// 4. 关联到 ZLMediaKit 的 StreamId
```

#### 生产环境的问题

**问题 1：SSRC 冲突**
- 多个通道使用相同 SSRC（`0100000001`）
- ZLM 可能混淆不同流
- RTP 包识别失败

**问题 2：无法追踪流**
- 无法从 SSRC 反查通道
- 无法管理多路并发流
- 调试困难

**问题 3：不符合 GB28181 标准**
- GB28181 要求 SSRC 在平台级唯一
- 设备和平台的 SSRC 应不同

#### ✅ 推荐解决方案

**方案 1：内存自增（轻量级）**

```php
class SsrcManager
{
    private static int $counter = 1000000000;
    private static array $usedSsrc = [];
    
    public static function allocate(string $deviceId, string $channelId): string
    {
        $key = "{$deviceId}:{$channelId}";
        
        // 复用已分配的 SSRC
        if (isset(self::$usedSsrc[$key])) {
            return self::$usedSsrc[$key];
        }
        
        // 生成新 SSRC
        $ssrc = str_pad((string)self::$counter, 10, '0', STR_PAD_LEFT);
        self::$counter++;
        
        // 缓存
        self::$usedSsrc[$key] = $ssrc;
        
        return $ssrc;
    }
}

// 使用：
$ssrc = SsrcManager::allocate($deviceId, $channelId);
$sdp .= "y={$ssrc}\r\n";
```

**方案 2：Redis持久化（推荐生产）**

```php
class SsrcManager
{
    private \Redis $redis;
    
    public function allocate(string $deviceId, string $channelId): string
    {
        $key = "gb28181:ssrc:{$deviceId}:{$channelId}";
        
        // 1. 尝试获取已有 SSRC
        $ssrc = $this->redis->get($key);
        if ($ssrc) {
            return $ssrc;
        }
        
        // 2. 生成新 SSRC（原子自增）
        $counter = $this->redis->incr('gb28181:ssrc:counter');
        $ssrc = str_pad((string)(1000000000 + $counter), 10, '0', STR_PAD_LEFT);
        
        // 3. 缓存（24小时过期）
        $this->redis->setex($key, 86400, $ssrc);
        
        // 4. 反向映射（SSRC -> Channel）
        $this->redis->hSet('gb28181:ssrc:map', $ssrc, json_encode([
            'device_id' => $deviceId,
            'channel_id' => $channelId,
            'created_at' => time(),
        ]));
        
        return $ssrc;
    }
    
    public function getChannelBySsrc(string $ssrc): ?array
    {
        $data = $this->redis->hGet('gb28181:ssrc:map', $ssrc);
        return $data ? json_decode($data, true) : null;
    }
}
```

### 2. ⚠️ 实时视频点播流程不完整

#### 当前实现的流程

```
Client -> GB28181Handler
         ↓
1. startLiveVideo()
   - 调用 ZLM openRtpServer() 分配端口
   - 构建 SDP（包含 ZLM 端口）
   - 发送 INVITE 到设备
   ✅ 已实现

2. handleInviteResponse()
   - 解析设备 200 OK 中的 SDP
   - 提取设备 SSRC
   - 生成播放地址
   ✅ 已实现

3. ❌ 缺失：通知 ZLM 设备的 SSRC
   - ZLM 需要知道设备 SSRC 才能接收流
   - 需要调用 ZLM 的 API 更新 SSRC
```

#### AKStream 的完整流程

```csharp
// 1. 分配 SSRC（从数据库）
var ssrc = GetOrCreateSsrc(deviceId, channelId);

// 2. ZLM 开启 RTP 端口
var result = zlmClient.OpenRtpServer(streamId, port, ssrc);

// 3. 发送 INVITE（SDP 包含服务器 SSRC）
SendInvite(channelId, sdp);

// 4. 收到设备 200 OK（提取设备 SSRC）
var deviceSsrc = ParseSdp(response);

// 5. ⚠️ 关键：告知 ZLM 设备 SSRC
zlmClient.UpdateRtpServerSsrc(streamId, deviceSsrc);

// 6. 设备开始推流 → ZLM 接收 → 生成播放地址
```

#### 修复建议

在 `GB28181Handler::handleInviteResponse()` 中添加：

```php
if ($ssrc && $this->zlmClient) {
    // ✅ 通知 ZLM 设备的 SSRC
    $result = $this->zlmClient->updateRtpServerSsrc($streamId, $ssrc);
    if (!$result || $result['code'] !== 0) {
        $this->log("ZLM SSRC 更新失败", 'ERROR');
    }
}
```

需要在 `ZLMClient.php` 中实现：

```php
public function updateRtpServerSsrc(string $streamId, string $ssrc): ?array
{
    return $this->request('updateRtpServerSSRC', [
        'stream_id' => $streamId,
        'ssrc' => $ssrc,
    ]);
}
```

### 3. ❌ 缺失数据库持久化（AKStream 核心设计）

#### AKStream 的核心理念

> **"AKStream 所有工作都基于数据库，所有推流、拉流、视频录制等操作均基于数据库中的 VideoChannel 表"**

#### VideoChannel 表的作用

```csharp
public class VideoChannel
{
    // 核心标识
    public string MainId { get; set; }           // 主键（SSRC 的 CRC32）
    public string DeviceId { get; set; }         // 设备 ID
    public string ChannelId { get; set; }        // 通道 ID
    
    // 流媒体绑定
    public string MediaServerId { get; set; }    // 归属流媒体服务器
    public string Ssrc { get; set; }             // 唯一 SSRC
    public string StreamId { get; set; }         // ZLM Stream ID
    
    // 激活状态
    public bool Enabled { get; set; }            // 是否激活
    public bool AutoVideo { get; set; }          // 自动推拉流
    public bool AutoRecord { get; set; }         // 自动录制
    
    // 通道信息
    public string ChannelName { get; set; }
    public string Manufacturer { get; set; }
    public string DeviceType { get; set; }
}
```

#### 为什么需要数据库？

1. **SSRC 全局唯一**: 数据库保证不重复
2. **多流媒体服务器**: 通道需要绑定到特定 ZLM 实例
3. **激活机制**: 只有 `Enabled=true` 的通道才能点播
4. **自动推拉流**: 设备上线自动启动流
5. **录制计划**: 绑定录制模板
6. **统计分析**: 流量、在线时长

#### 本项目的现状

- ✅ 有 `DeviceManager`（内存存储设备信息）
- ✅ 有 `$catalogs` 数组（内存存储目录）
- ❌ 无通道表（无法管理通道生命周期）
- ❌ 无 SSRC 持久化（重启丢失）
- ❌ 无流媒体服务器绑定（单机可用）

#### 是否必须实现？

**短期（开发/测试）**: ❌ 不必须
- 当前内存方案够用
- 单机部署、少量设备

**中期（小规模生产）**: ⚠️ 建议实现
- Redis 存储 SSRC 和会话
- 避免重启丢失状态

**长期（规模生产）**: ✅ 必须实现
- 数据库持久化
- 支持集群、多流媒体服务器
- 符合 AKStream 设计理念
