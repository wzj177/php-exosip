# 设备配置扩展方案

> 本文档说明如何扩展 GB28181 设备配置字段，并实现 API 与网关的配置同步。

## 📊 扩展字段说明

### 数据库新增字段 (gv_devices 表)

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `subscribe_catalog` | TINYINT(1) | 0 | 是否订阅目录变更 |
| `subscribe_alarm` | TINYINT(1) | 0 | 是否订阅报警事件 |
| `subscribe_position` | TINYINT(1) | 0 | 是否订阅位置上报 |
| `subscribe_ptz` | TINYINT(1) | 0 | 是否订阅PTZ控制反馈(2022) |
| `subscribe_expires` | INT | 3600 | 订阅有效期（秒） |
| `position_interval` | INT | 60 | 位置上报间隔（秒） |
| `catalog_interval` | INT | 3600 | 目录更新周期（秒），0=禁用 |
| `last_catalog_at` | DATETIME | NULL | 上次目录查询时间 |
| `charset` | ENUM | 'gb2312' | 设备XML字符集 |
| `stream_index` | VARCHAR(16) | 'auto' | 码流索引: auto/0/1 |
| `filter_channel_types` | JSON | NULL | 过滤通道类型，如 [134,135] |
| `record_mode` | ENUM | 'center' | 录像模式: center/fuzzy |
| `catalog_structure` | ENUM | 'area' | 目录结构: area/device |
| `subscription_status` | JSON | NULL | 订阅状态信息 |

> **注意**: 
> - `rtp_trans_mode` 字段已存在，值含义：0=UDP, 1=TCP被动(设备连平台), 2=TCP主动(平台连设备)
> - **收流IP架构**：收流IP不在设备级别配置，而是通过通道绑定的 `media_server_id` 关联到 `gv_media_servers` 表的 `stream_ip` 字段

## 📋 各字段使用流程详解

### 1. 字符集 (charset)

**作用**: 解析设备上报的 XML 时使用的编码。

**使用位置**: `GB28181Handler.php` 的 `normalizeXmlEncoding()` 方法

```php
// GB28181Handler.php - handleMessage() 中
private function normalizeXmlEncoding(string $body): string
{
    // 获取设备配置的字符集
    $deviceId = $this->extractDeviceId($fromUri);
    $device = $this->deviceManager->getDeviceObject($deviceId);
    $charset = $device?->charset ?? 'gb2312';
    
    // 如果声明的编码与实际不符，进行转换
    if ($charset === 'gb2312') {
        // 检测实际编码
        $encoding = mb_detect_encoding($body, ['UTF-8', 'GB2312', 'GBK'], true);
        if ($encoding && $encoding !== 'UTF-8') {
            $body = mb_convert_encoding($body, 'UTF-8', $encoding);
        }
    }
    
    return $body;
}
```

**配置同步时机**:
- 设备注册时从 API 拉取
- 用户在后台修改后通过 Redis 推送更新

### 2. 通道过滤 (filter_channel_types)

**作用**: 在解析 Catalog 时过滤掉不需要的通道类型（如报警输入/输出）。

**通道类型代码** (GB28181 规范):
| 代码 | 类型 |
|------|------|
| 131 | 球机 |
| 132 | 半球 |
| 133 | 固定枪机 |
| 134 | 报警输入 |
| 135 | 报警输出 |
| 136 | 语音输入 |
| 137 | 语音输出 |
| 138 | 其他 |

**使用位置**: `CatalogCommand.php` 或 `GB28181Handler.php`

```php
// CatalogCommand.php - parse() 方法中
public function parse(\SimpleXMLElement $xml, string $deviceId, array $context = []): array
{
    $device = $context['device_manager']?->getDeviceObject($deviceId);
    $filterTypes = $device?->filterChannelTypes ?? [];
    
    $channels = [];
    foreach ($xml->DeviceList->Item as $item) {
        $channelId = (string)$item->DeviceID;
        
        // 通道类型：取第11-13位
        $typeCode = (int)substr($channelId, 10, 3);
        
        // 如果在过滤列表中，跳过
        if (in_array($typeCode, $filterTypes)) {
            continue;
        }
        
        $channels[] = [
            'channel_id' => $channelId,
            'name' => (string)$item->Name,
            'status' => (string)$item->Status,
            // ...
        ];
    }
    
    return [
        'cmd_type' => 'Catalog',
        'channels' => $channels,
        'filtered_count' => count($filterTypes),
    ];
}
```

### 3. 收流 IP 架构说明

**架构设计**: 收流 IP 不在设备级别配置，而是通过流媒体服务器表管理

**数据库表关系**:
```
gv_device_channels (通道表)
    └─ media_server_id → gv_media_servers (流媒体服务器表)
                             ├─ host (API 地址)
                             └─ stream_ip (收流地址，用于 SDP)
```

**流程说明**:
1. 通道绑定流媒体服务器：每个通道配置 `media_server_id`
2. 流媒体服务器配置收流 IP：`gv_media_servers.stream_ip`
3. 构建 SDP 时查询：根据通道的 `media_server_id` 查询对应的 `stream_ip`

**使用位置**: `CommandDispatcher.php` - `handleStartLiveVideo()`

```php
// CommandDispatcher.php - handleStartLiveVideo()
private function handleStartLiveVideo(string $requestId, string $channelId, array $params): array
{
    // 1. 查询通道信息（包含 media_server_id）
    $channel = $this->channelDao->getChannelById($channelId);
    if (!$channel || !$channel['media_server_id']) {
        return $this->errorResponse($requestId, 'Channel not bound to media server');
    }
    
    // 2. 查询流媒体服务器配置
    $mediaServer = $this->mediaServerDao->getById($channel['media_server_id']);
    if (!$mediaServer) {
        return $this->errorResponse($requestId, 'Media server not found');
    }
    
    // 3. 使用流媒体服务器的收流 IP
    $streamIp = $mediaServer['stream_ip'] ?: $mediaServer['host']; // 回退到 host
    
    // 4. 构建 SDP
    $sdp = SdpBuilder::buildLiveVideoSdp(
        serverId: $this->config['server_id'],
        mediaIp: $streamIp,  // 使用流媒体服务器的收流 IP
        mediaPort: $zlmPort,
        ssrc: $ssrc,
        tcpMode: $channel['rtp_trans_mode'] ?? 0
    );
    
    // ...
}
```

**优势**:
- 灵活性：支持多流媒体服务器部署
- 解耦：通道级别绑定，而非设备级别
- 可扩展：便于负载均衡和流量分发

### 4. 码流索引 (stream_index)

**作用**: 点播时请求的码流类型（主码流/子码流）。

**使用位置**: `SdpBuilder.php` 或 INVITE 请求构建

```php
// SdpBuilder.php - 根据码流索引选择编码
public static function buildLiveVideoSdp(..., string $streamIndex = 'auto'): string
{
    // 码流索引影响 SDP 中的媒体格式选择
    // auto: 让设备自动选择
    // 0: 主码流（高分辨率）
    // 1: 子码流（低分辨率）
    
    $payloadType = match($streamIndex) {
        '0' => 96,   // 主码流
        '1' => 97,   // 子码流
        default => 96,  // 默认主码流
    };
    
    $sdp .= "m=video {$mediaPort} RTP/AVP {$payloadType}\r\n";
    // ...
}
```

### 5. RTP 传输模式 (rtp_trans_mode)

**值说明**:
- `0` = UDP（最常用，低延迟）
- `1` = TCP 被动（设备主动连接平台，适合公网设备）
- `2` = TCP 主动（平台主动连接设备，需设备端口可达）

**使用位置**: `SdpBuilder.php`

```php
// SdpBuilder.php
public static function buildLiveVideoSdp(..., int $tcpMode = 0): string
{
    // 根据传输模式设置 SDP
    if ($tcpMode === 0) {
        // UDP
        $sdp .= "m=video {$mediaPort} RTP/AVP 96\r\n";
    } elseif ($tcpMode === 1) {
        // TCP 被动：设备连接平台
        $sdp .= "m=video {$mediaPort} TCP/RTP/AVP 96\r\n";
        $sdp .= "a=setup:passive\r\n";
        $sdp .= "a=connection:new\r\n";
    } else {
        // TCP 主动：平台连接设备
        $sdp .= "m=video {$mediaPort} TCP/RTP/AVP 96\r\n";
        $sdp .= "a=setup:active\r\n";
        $sdp .= "a=connection:new\r\n";
    }
    
    return $sdp;
}
```

## 📡 API 与网关配置同步方案

### 方案一：Redis 命令通知（推荐）

当 API 更新设备配置后，通过 Redis 队列发送 `update_device_config` 命令：

```php
// API 层 - 更新设备配置后发送通知
class DeviceService
{
    public function updateDeviceConfig(string $deviceId, array $config): bool
    {
        // 1. 更新数据库
        $this->deviceDao->update($deviceId, $config);

        // 2. 发送配置更新通知到网关
        $this->getGb28181Client()->sendCommand($deviceId, 'update_device_config', [
            'config' => $config
        ]);

        return true;
    }
}
```

网关层处理：

```php
// CommandDispatcher.php - 添加处理方法
case 'update_device_config':
    return $this->handleUpdateDeviceConfig($requestId, $deviceId, $params);

private function handleUpdateDeviceConfig(
    string $requestId,
    string $deviceId,
    array $params
): array {
    $config = $params['config'] ?? [];
    
    // 更新内存中的设备配置
    $result = $this->deviceManager->updateDeviceConfig($deviceId, $config);
    
    if (!$result) {
        return $this->errorResponse($requestId, "Device not found: {$deviceId}");
    }

    // 如果订阅配置变化，触发订阅更新
    $device = $this->deviceManager->getDeviceObject($deviceId);
    if ($device) {
        $this->handleSubscriptionChange($device);
    }

    return [
        'success' => true,
        'request_id' => $requestId,
        'message' => 'Device config updated'
    ];
}
```

## 🔄 配置变更触发订阅

当订阅配置变化时，需要自动处理：

```php
// GB28181Handler.php 或 CommandDispatcher.php
private function handleSubscriptionChange(Device $device): void
{
    $deviceId = $device->deviceId;
    $deviceIp = $device->received_ip ?? $device->ip;
    $devicePort = $device->received_port ?? $device->port;

    // 获取当前需要的订阅
    $requiredEvents = $device->getSubscribeEvents();
    $currentSubscriptions = array_keys($device->subscriptions);

    // 需要新增的订阅
    $toSubscribe = array_diff($requiredEvents, $currentSubscriptions);
    foreach ($toSubscribe as $eventType) {
        $this->sendSubscribe($deviceId, $deviceIp, $devicePort, $eventType, $device->subscribeExpires);
    }

    // 需要取消的订阅
    $toUnsubscribe = array_diff($currentSubscriptions, $requiredEvents);
    foreach ($toUnsubscribe as $eventType) {
        $this->sendUnsubscribe($deviceId, $deviceIp, $devicePort, $eventType);
    }
}
```
