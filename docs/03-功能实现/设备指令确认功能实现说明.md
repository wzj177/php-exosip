## 📋 功能概述

实现设备对控制指令的确认响应处理，当平台发送 PTZ、录像控制等指令后，设备会返回 `200 OK` 响应表示"已收到指令"。本功能捕获这个响应并通知业务系统。

### 重要说明

⚠️ **关键区别**：
- **200 OK 响应** = 设备确认收到指令（传输成功）
- **MESSAGE 请求** = 设备返回执行结果（业务成功）

这是两个独立的流程：
1. 平台发送 `MESSAGE DeviceControl` → 设备回复 `200 OK` → 触发 `command_confirmed`
2. 设备执行指令 → 设备发送 `MESSAGE` (带 XML 结果) → 触发 `handleMessage`

{

    $type = $event->getType();

#### 2.2 handleMessageResponse() - 核心处理逻辑

```php
private function handleMessageResponse(\SipEvent $event): void
{
    $code = $event->getCode();
    $callId = $event->getCallId();
    $toUri = $event->getToUri();
    $deviceId = $this->extractDeviceId($toUri);
    
    // 提取 CSeq 号码
    $cseqHeader = $event->getHeader('CSeq');
    $cseqNumber = null;
    $method = 'MESSAGE';
    
    if ($cseqHeader && preg_match('/(\d+)\s+(\w+)/', $cseqHeader, $matches)) {
        $cseqNumber = (int)$matches[1];
        $method = $matches[2];
    }
    
    $this->log("收到 MESSAGE 200 OK: 设备 {$deviceId}, Call-ID: {$callId}, CSeq: {$cseqNumber}");
    
    // 发送到 Hook API
    $this->postTask('command_confirmed', [
        'device_id' => $deviceId,
        'call_id' => $callId,
        'cseq' => $cseqNumber,
        'status_code' => $code,
        'method' => $method,
        'timestamp' => time(),
    ]);
}
```

**验证点**:
- ✅ 能够提取 `device_id`（从 To URI）
- ✅ 能够提取 `call_id`
- ✅ 能够解析 `CSeq` 头（格式: "20 MESSAGE"）
- ✅ 调用 `postTask('command_confirmed')`

## 🎯 应用场景

### 场景1: PTZ 控制确认

**需求**: 记录 PTZ 控制指令的发送状态

**实现**:
```php
// 数据库表: device_ptz_logs
// cseq | device_id | direction | status     | confirmed_at
// -----|-----------|-----------|------------|-------------
// 20   | 510107... | up        | confirmed  | 2026-01-13 10:30:00

private function handleCommandConfirmed(array $body): void
{
    $cseq = $body['cseq'];
    $deviceId = $body['device_id'];
    
    DB::table('device_ptz_logs')
        ->where('cseq', $cseq)
        ->where('device_id', $deviceId)
        ->update([
            'status' => 'confirmed',
            'confirmed_at' => now(),
        ]);
}
```

### 场景2: 录像任务状态追踪

**需求**: 标记录像任务已被设备接收

**实现**:
```php
// 数据库表: recording_tasks
// id | device_id | status     | created_at | confirmed_at
// ---|-----------|------------|------------|-------------
// 1  | 510107... | processing | 10:30:00   | 10:30:01

private function handleCommandConfirmed(array $body): void
{
    $callId = $body['call_id'];
    
    // 根据 call_id 关联原始任务
    $task = DB::table('recording_tasks')
        ->where('call_id', $callId)
        ->first();
    
    if ($task && $task->status === 'pending') {
        DB::table('recording_tasks')
            ->where('id', $task->id)
            ->update([
                'status' => 'processing',
                'confirmed_at' => now(),
            ]);
    }
}
```

### 场景3: 指令重试机制

**需求**: 如果设备3秒内未响应，自动重试

**实现**:
```php
// 发送指令时记录
class CommandService
{
    public function sendPtzCommand($deviceId, $direction)
    {
        $callId = $this->sipClient->sendMessage(...);
        
        // 记录待确认的指令
        Redis::setex("command_pending:{$callId}", 3, json_encode([
            'device_id' => $deviceId,
            'action' => 'ptz',
            'direction' => $direction,
            'sent_at' => time(),
        ]));
    }
}

// 收到确认时删除
private function handleCommandConfirmed(array $body): void
{
    $callId = $body['call_id'];
    Redis::del("command_pending:{$callId}");
}

// 定时任务检查超时
public function checkCommandTimeout()
{
    $keys = Redis::keys('command_pending:*');
    foreach ($keys as $key) {
        $data = json_decode(Redis::get($key), true);
        if (time() - $data['sent_at'] > 3) {
            // 重试指令
            $this->retryCommand($data);
        }
    }
}
```

## ⚠️ 常见问题

### Q1: 为什么 200 OK 没有 body？

**A**: 符合 SIP 协议规范。
- `200 OK` 只是确认收到请求（传输层成功）
- 实际执行结果通过后续的 `MESSAGE` 请求返回（应用层成功）

### Q2: 如何关联原始请求？

**A**: 使用 `Call-ID` 或 `CSeq`。
- **Call-ID**: 全局唯一，适合跨会话追踪
- **CSeq**: 会话内递增，适合同一设备的多个指令

### Q3: 如果设备不响应怎么办？

**A**: 实现超时重试机制。
1. 发送指令时记录到 Redis（TTL=3秒）
2. 收到 `command_confirmed` 时删除记录
3. 定时任务扫描超时的指令并重试

### Q4: `handleMessageResponse` 和 `handleMessage` 有什么区别？

**A**: 
- `handleMessageResponse`: 处理 **响应**（200 OK），表示设备收到指令
- `handleMessage`: 处理 **请求**（MESSAGE），表示设备发送数据
