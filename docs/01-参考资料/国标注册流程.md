根据你提供的两个 REGISTER 请求，这是典型的 **GB28181** 协议中设备向平台（SIP Server）注册的流程，遵循 **SIP Digest Authentication** 两步认证机制。第一个 REGISTER 是无认证信息的初始注册请求，服务器应返回 **401 Unauthorized** 响应，并携带 **WWW-Authenticate** 头，用于发起挑战（challenge）。

---

### 第一个 REGISTER 请求后，服务器应返回如下 401 响应：

```sip
SIP/2.0 401 Unauthorized
Via: SIP/2.0/UDP 10.38.224.158:15060;rport=15060;branch=z9hG4bK69207bf3
From: <sip:34020000001320623539@3402000000>;tag=198389ee
To: <sip:34020000001320623539@3402000000>;tag=as7d3f2a1b
Call-ID: 4BED9B165FBEEF49@10.38.224.158
CSeq: 1 REGISTER
WWW-Authenticate: Digest realm="3402000000", nonce="edaf128c9ef7df9be6610739e74106ed", algorithm=MD5, qop="auth"
Server: GB28181 SIP Server
Content-Length: 0
```

### 说明：

- **状态码 `401 Unauthorized`**：表示需要身份验证。
- **`WWW-Authenticate` 头**：
  - `realm`: 通常为国标中平台的域（如 `3402000000`）。
  - `nonce`: 由服务器生成的随机字符串，用于防重放攻击。你第二个 REGISTER 中使用的 `nonce="edaf128c9ef7df9be6610739e74106ed"` 正好匹配此处。
  - `algorithm=MD5`：GB28181 国标强制使用 MD5 哈希。
  - `qop="auth"`（可选但推荐）：表示“quality of protection”，GB/T 28181-2016 中虽未强制要求，但主流平台（如海康、大华）通常包含。

> 注意：`To` 头中服务器应添加 `tag` 参数（如 `tag=as7d3f2a1b`），这是 SIP RFC 3261 的要求。

---

### 后续流程：

设备收到 401 后，使用如下公式计算 `response`：

```
HA1 = MD5(username:realm:password)
HA2 = MD5("REGISTER":uri)
response = MD5(HA1:nonce:HA2)
```

其中：
- `username` = `"34020000001320623539"`
- `realm` = `"3402000000"`
- `uri` = `"sip:34020000002000000001@3402000000"`
- `nonce` = 服务器返回的值
- `password` = 预共享密钥（设备在平台注册时配置的）

你第二个 REGISTER 中的 `response="0edb6dcfc2f3d62ce6b12f49e44e9868"` 就是按此计算出的摘要。

如果验证通过，服务器将返回 **200 OK** 完成注册。

--- 

在你提供的第二个 REGISTER 请求中，设备已经携带了 **Digest 认证信息**（`Authorization` 头），说明它已根据服务器在第一个响应中返回的 `WWW-Authenticate` 挑战完成了身份验证计算。

此时，**服务器验证凭据成功后，应回复 `200 OK` 表示注册成功**。

---

### 第二个 REGISTER 请求后，服务器应返回的 200 OK 响应如下：

```sip
SIP/2.0 200 OK
Via: SIP/2.0/UDP 10.38.224.158:15060;rport=15060;branch=z9hG4bK69209317
From: <sip:34020000001320623539@3402000000>;tag=7d0010bc
To: <sip:34020000001320623539@3402000000>;tag=as8f4e1c2d
Call-ID: 0F6AD68B75685140@10.38.224.158
CSeq: 271 REGISTER
Contact: <sip:34020000001320623539@10.38.224.158:15060>;expires=3600
Server: GB28181 SIP Server
Content-Length: 0
```

---

### 关键字段说明：

- **`SIP/2.0 200 OK`**：表示注册成功，认证通过。
- **`To` 头必须包含 `tag`**：这是 SIP RFC 3261 对 2xx 响应的要求（即使原始请求中 `To` 无 tag，响应也需添加）。
- **`Contact` 头**：可选回显，用于告知设备当前注册的 Contact 地址及有效期（`expires=3600`），符合 GB/T 28181 要求。
- **`Via`**：必须原样回传请求中的 `Via`（包括 `branch` 和 `rport`），SIP 代理/服务器需保证路由正确。
- **`CSeq`**：必须与请求中的 `CSeq` 一致（271 REGISTER）。
- **`Server`**：自定义字段，便于调试，非必须。

> 注意：GB/T 28181-2016 第 6.2.2 条规定，平台收到带有效认证的 REGISTER 后，应返回 200 OK，完成注册流程。

---

### 补充说明（安全与兼容性）：

- 若 `response` 计算错误、`nonce` 过期或 `username` 不存在，服务器应返回 **403 Forbidden** 或 **401 Unauthorized**（重新挑战）。
- `nonce` 应具备时效性和唯一性，防止重放攻击。
- 在实际平台实现中（如基于 eXosip），需校验：
  - `realm` 是否匹配平台域（`3402000000`）
  - `username` 是否为合法设备 ID（20 位国标编码）
  - `uri` 是否为目标平台地址（`sip:34020000002000000001@3402000000`）
