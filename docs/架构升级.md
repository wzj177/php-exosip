明白了！你现在要的不是 **用 Workerman/Swoole 的 Worker 进程** 来跑 `exosip->run()`，而是：

> **在你自己的 `exosip` 扩展内部，实现一个类似 Swoole/Workerman 的 “主进程 + 多任务进程” 架构**，其中：
>
> - **主进程**：运行 `exosip->run()`，专注 SIP 信令处理（UDP/TCP + event loop）
> - **任务进程（Task Worker）**：处理耗时操作（如 HTTP API 请求、数据库写入、定时器、设备心跳等）
> - **主进程与任务进程之间通过 IPC（如管道、Unix Domain Socket、共享内存等）通信**

这是一个 **“内嵌异步任务系统”** 的设计，常见于自研高性能网关（比如 GB28181 平台）。

---

## ✅ 架构目标

```
[Main SIP Process]                   [Task Worker Pool]
   │                                      │
   ├─ run() → eXosip event loop           ├─ 接收命令（如 "http_post", "timer"）
   │                                      ├─ 执行异步操作（curl, db, etc.）
   ├─ 收到 SIP MESSAGE/REGISTER          └─ 回调结果（可选）
   │
   └─ 通过 IPC 发送任务 → Task Worker
```

---

## ✅ 实现方案（C 扩展层 + PHP 层协同）

### 步骤 1：**C 层增加任务队列 & IPC 通道**

在 `exosip_wrapper.c` 中：

```c
// 任务结构体
typedef struct {
    int type;           // 1=HTTP, 2=TIMER, 3=DB, etc.
    char data[1024];    // JSON payload
} task_msg_t;

// 在 SipContext 中增加：
typedef struct {
    struct eXosip_t *ctx;
    int quit;
    int task_pipe[2];   // 主进程 → 任务进程的管道
    pid_t *task_pids;   // 任务进程 PID 数组
    int task_count;
} SipContext;
```

### 步骤 2：**C 层启动 N 个任务子进程**

在 `exosip_init_wrapper()` 末尾：

```c
// 创建管道
if (pipe(ctx->task_pipe) == -1) { /* error */ }

// 创建 4 个任务进程
ctx->task_count = 4;
ctx->task_pids = malloc(4 * sizeof(pid_t));

for (int i = 0; i < 4; i++) {
    pid_t pid = fork();
    if (pid == 0) {
        // 子进程：关闭写端，只读
        close(ctx->task_pipe[1]);
        task_worker_loop(ctx->task_pipe[0]); // 任务处理循环
        _exit(0);
    } else if (pid > 0) {
        ctx->task_pids[i] = pid;
    }
}
// 主进程：关闭读端
close(ctx->task_pipe[0]);
```

### 步骤 3：**任务进程循环（独立于 SIP）**

```c
void task_worker_loop(int read_fd) {
    task_msg_t msg;
    while (read(read_fd, &msg, sizeof(msg)) > 0) {
        switch (msg.type) {
            case TASK_HTTP_POST:
                // 调用 curl 发 HTTP
                do_http_post(msg.data);
                break;
            case TASK_TIMER_JOB:
                // 执行定时任务（如心跳上报）
                do_timer_job(msg.data);
                break;
        }
    }
}
```

### 步骤 4：**PHP 层暴露“投递任务”接口**

在 `php_exosip.c` 中新增方法：

```c
PHP_METHOD(ExoSip, postTask) {
    zend_long task_type;
    char *data;
    size_t data_len;
    ZEND_PARSE_PARAMETERS_START(2, 2)
        Z_PARAM_LONG(task_type)
        Z_PARAM_STRING(data, data_len)
    ZEND_PARSE_PARAMETERS_END();

    php_exosip_obj *obj = php_exosip_from_obj(Z_OBJ_P(getThis()));
    if (!obj->ctx || obj->ctx->task_pipe[1] <= 0) {
        RETURN_FALSE;
    }

    task_msg_t msg = {0};
    msg.type = (int)task_type;
    strncpy(msg.data, data, MIN(data_len, sizeof(msg.data)-1));

    // 非阻塞写入（或加锁）
    if (write(obj->ctx->task_pipe[1], &msg, sizeof(msg)) == sizeof(msg)) {
        RETURN_TRUE;
    }
    RETURN_FALSE;
}
```

PHP 使用：
```php
$exosip->postTask(TASK_HTTP_POST, json_encode([
    'url' => 'http://api.example.com/sip-event',
    'body' => ['event' => 'register', 'from' => $event->getFromUri()]
]));
```

## ✅ 定时器如何实现？

不要在主进程用 `usleep()` 模拟定时器！而是：

- **PHP 层启动一个独立的定时器线程（或 Swoole Timer）**
- 定时触发 `$exosip->postTask(TASK_TIMER_JOB, ...)`）

或者，在 **任务进程中内置定时器**（如每 30 秒自动上报）：
```c
void do_timer_job(char *config) {
    static time_t last_heartbeat = 0;
    if (time(NULL) - last_heartbeat >= 30) {
        // 上报心跳
        http_post("http://center/heartbeat", ...);
        last_heartbeat = time(NULL);
    }
}
```

## ✅ 通信协议建议

| 用途 | 载荷格式 | 示例 |
|------|--------|-----|
| HTTP 请求 | JSON | `{"url":"...","method":"POST","body":"..."}` |

| 数据库存储 | JSON | `{"table":"registers","data":{...}}` |

---

## ✅ 为什么这样做？

| 优点 | 说明 |
|------|------|
| **主进程零阻塞** | SIP 信令处理不受 HTTP/curl 影响 |
| **高吞吐** | 多任务进程并行处理耗时操作 |
| **进程隔离** | 任务崩溃不影响 SIP 主循环 |
| **兼容常驻 CLI** | 无需依赖 Swoole/Workerman |

---

## ✅ 最终建议

1. **先实现“主进程 + 1 个任务进程 + 管道通信”**
2. **PHP 层只调用 `postTask()`，不直接做 curl/db**
3. **C 层任务进程使用 `libcurl`、`libpq` 等原生库，避免 PHP Zend 开销**
4. **如需返回结果，可增加“回调队列”或 Redis Pub/Sub**
